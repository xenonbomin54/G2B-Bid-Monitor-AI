# 자가 라벨링 기록

대회 규칙 2-2 는 라벨 생성 단계에 한해 외부 LLM 사용을 허용한다.
규칙 3(재현 가능성)은 **라벨 생성 코드·프롬프트·사용 모델(버전)과 생성된 라벨 데이터**를
2차 평가에 제출하도록 요구한다. 소급 작성이 불가능하므로 처음부터 이 폴더에 기록한다.

## 왜 필요한가

`dev.jsonl.gz` 200건은 README 가 명시하듯 평가 데이터 분포를 대표하지 않는다.
`train_unlabeled` 20,000건과 견주면 큰 계약에 편중돼 있다.

| 판로지원 밴드 | dev | 실제 20,000건 |
|---|---|---|
| A (1억 미만) | 53.0% | **71.7%** |
| C (고시금액 이상) | 22.5% | **11.2%** |

그래서 dev 로 F1 을 올려도 리더보드가 따라오지 않았다(dev 0.6326 → 리더보드 0.42458).
**실제 분포를 반영한 검증셋**이 있어야 개선이 실제 점수로 이어지는지 확인할 수 있다.

## 대상

`out/holdout200.jsonl.gz` — `train_unlabeled` 20,000건에서 판로지원 밴드 ·
적용계약법 · 업무구분 비율을 유지해 뽑은 층화표본 200건 (모집단과 오차 1%p 이내).
추출 코드: `tools/make_holdout.py`, 시드 20260906.

## 입력 제약 (규칙 준수)

- 외부 LLM 에는 **대회 제공 자료만** 입력한다 — `open/` 아래 파일만 사용.
- 웹 검색·외부 문서 결합 기능으로 원문을 조회하지 않는다.
- 익명화된 식별자(기관명·공고번호)를 복원하려 시도하지 않는다.

## 파일

| 파일 | 내용 |
|---|---|
| `prompt.md` | 라벨 생성에 사용한 프롬프트 전문 |
| `provenance.json` | 사용 모델·버전·시각·설정 |
| `labels.csv` | 생성된 라벨 (dev_labels.csv 와 같은 49열 형식) |
| `notes.md` | 판정이 애매했던 사례와 근거 |

## 사용법

```bash
python3 tools/make_holdout.py                 # 층화표본 추출 (재현)
python3 tools/label_holdout.py --report       # 라벨링 대상 요약
python3 tools/evaluate.py --runner api \
    --data out/holdout200.jsonl.gz \
    --labels labeling/labels.csv              # 홀드아웃 채점
```
